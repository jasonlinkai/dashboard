# 決策紀錄

這份文件記錄「為什麼這樣做」，讓之後接手的人（包括新開 session 的 AI）不會重做已經否決的方案、
也不會漏掉某個決定牽動的其他地方。程式碼本身說明「怎麼做」；這裡只寫理由與連帶規則。

**維護方式**：每次做出會影響之後判斷的決定（資料格式、版面規則、互動方式、刻意不做的事），
在對應章節補一條，或在最後的「變更紀錄」加一筆。推翻舊決定時，改寫那一條並註明原因，不要留下互相矛盾的兩條。

---

## 1. 資料模型：板塊（card）

- **每種板塊的「第一個」內容放在設定的頂層欄位**（`weather`、`markets`、`bus`、`trains`、`news`/`newsOrder`、`todos`），
  id 就是種類名稱（`weather`）。同類的其他板塊放在 `extras`，各自帶自己那份欄位（id 例如 `weather-k3x9`）。
  - 理由：舊版設定檔只有頂層欄位，這樣舊檔不用轉換就能讀；卡片元件透過 `CardSettings` 看到的永遠是「自己的」設定，不用知道自己是第幾個。
  - 連帶規則：刪除某類的第一個板塊時，若還有同類 extra，**第一個 extra 會搬進頂層**（內容、名稱、位置一起搬）。
- **`absent`：哪些種類目前沒有任何板塊**（第一個也被刪了，或預設版型本來就沒有）。
  - 不變式：`absent` 裡的種類一定沒有 extras（驗證時若有，該種類視為存在）。
  - 刪掉某類最後一個板塊 → 加進 `absent`，頂層欄位**重設為預設值**（再新增時就是預設內容，也不會有看不到的舊資料佔用合計上限）。
  - 新增一個 absent 的種類 → 把「第一個」加回來，而不是建立 extra。
- **新增板塊一律從精簡內容開始**，不管從排版列、設定頁或手機捷徑新增：天氣、行情各 1 個項目（取第一個板塊的；種類 absent 時取預設值的第一個），公車、火車空的，新聞用第一個板塊（或預設）的來源，待辦空的。
  只有「恢復預設」補回版型裡的種類時才套用完整預設（2026-10-22：之前 absent 種類從排版列加回來會帶完整預設的 4 個天氣地點，跟設定頁新增的 1 個不一致）。
  - 舊設定檔沒有 `absent` 欄位 → 用預設值 `["todo"]`（舊檔的年代所有其他種類都在看板上；待辦是之後才加的）。
- **允許刪除所有板塊**（2026-10-21 起）。看板空了會顯示「看板上沒有板塊」與進入排版模式的按鈕；手機分頁會顯示新增捷徑。
  驗證也接受「某個方向所有板塊都隱藏」。
- **同類最多 3 個**（`MAX_PER_TYPE`）。同類共用一個 API 請求，伺服器有大小上限、TDX 每分鐘有額度，所以天氣地點、行情、公車、火車的上限是**同類所有板塊合計**（`overLimit`）。
- **待辦鎖頭**：每個待辦板塊各自有 `todoLocked`（存在設定裡，備份會帶著）。鎖定時不能勾選、新增、刪除；點鎖頭就解鎖（防誤觸，不是密碼保護）。新增的待辦板塊一律未鎖定。
- **待辦事項（todo）**：純本機資料，不打 API，所以每個板塊各自上限 30 項（`LIMITS.todos`），不算合計。項目直接在看板上新增、勾選、刪除；設定頁只有名稱與刪除。
- 設定只存在各裝置的 localStorage；**等於預設值時不存**，這樣預設值更新後會自動送到沒改過設定的裝置。
- 匯入的檔案不可信：所有欄位都經過 `validate()`。新欄位一定要在 `validate()` 補上舊檔沒有該欄位時的預設行為。

## 2. 預設版型（preset）

- 版型 = 每個方向（`wide`、`tall`）各一組「種類 → 格子」(`Preset` 型別，`PRESETS` 表)。目前只有 `default`。
- **版型裡沒列到的種類，套用版型時不會被加上**；最初的預設版型就沒有待辦事項，這是正常情況。
- 「恢復預設」= 套用版型：版型列到但使用者已刪除的種類會**以預設內容補回**；版型沒列到的板塊（extras、待辦）保留，放進空位，沒空位就隱藏。
- 之後要加更多版型：在 `PRESETS` 加一組，呼叫 `resetLayout(PRESETS.xxx)`；`validate(raw, preset)` 會用該版型決定沒有位置的種類放哪。若要記住使用者選了哪個版型，需要新增設定欄位（目前沒有）。

## 3. 版面（平板 / 桌機）

- 版面是 24×24 的格子（`GRID`），每個板塊一個方框 `{x, y, w, h}`。
- **兩個方向各自一份**：`wide`（桌機、平板橫放）與 `tall`（平板直放），各有自己的方框與隱藏清單。判斷方向的 media query 在 `layoutEdit.tsx` 與 `styles.css` 兩處，要同步改。
- **恢復預設只影響目前的方向**（2026-10-21 修正；之前兩個方向一起重設，使用者回報為 bug），而且要先跳出確認視窗；確認後直接結束排版模式（手機也是）。
- **所有種類共用同一個最小尺寸**：280×170 px（`MIN_PX`）。理由：任兩個板塊都能直接交換，不會因為某種類比較大而卡住。每種板塊的「小尺寸」樣式（`styles.css` 的 Small cards）要保證在最小尺寸下仍看得到標題、內容與資料來源列。
  - 最小尺寸以像素定義，換算成格數取決於螢幕大小（`minCells`）。另一個方向量不到，用「螢幕轉過來、周圍留白相同」估算（`minCellsElsewhere`，是近似值）。手機沒有版面，用 `BOARD_MIN`（4×3 格）。
  - 只有**這次被移動或改大小的板塊**要符合目前螢幕的最小值；沒動到的可以比較小（可能是在較大的螢幕上排的），不然在小螢幕上任何操作都會被擋。
- **任何放進版面的板塊都至少是最小尺寸**：新增時剛好是最小尺寸；從隱藏顯示回來時用原本的方框，但比最小值小就放大到最小值（2026-10-21 修正：之前沒空位時暫存的 4×3 方框會原樣放回來，比最小值小）。
- 新增時沒空位 → 先隱藏，在排版列出現「＋名稱」，騰出空間後再顯示。
- 隱藏只影響目前的方向，內容保留；刪除在設定頁。至少要留一個板塊不隱藏（避免手滑把看板清空；要清空請刪除）。
- 拖邊線會帶動相鄰板塊；鄰居被擠到最小值會繼續推下一個。
- 排版模式中，板塊內容不能點（`pointer-events: none`），只有移動鈕與「隱藏」能點。拖曳開始時對板塊做 pointer capture，所以**「隱藏」按鈕要排除在拖曳之外**，否則點擊會被導到板塊上（2026-10-21 修正）。
- 在排版列新增板塊**不開設定視窗**（使用者還在排版）；在設定頁新增則會直接打開新板塊的設定頁。
- 排版列左上角是燈泡圖示（取代原本一行操作提示文字），點了彈窗解釋兩個方向、移動與縮放、最小尺寸、隱藏與刪除、新增、恢復預設（`LayoutHelp.tsx`）。**改了排版規則要同步改這段說明文字。**
- 排版列上隱藏板塊的「＋名稱」放在自己的橫向捲動區（最多佔 45% 寬），不會把「新增板塊」與完成按鈕擠出畫面。

## 4. 手機

- **手機的排版模式只能「恢復預設」**（2026-10-22 加回）：右上角一樣有排版圖示，排版列只有燈泡（手機版說明）、恢復預設、完成；不能移動、縮放、隱藏或新增（新增在設定頁）。
  手機的恢復預設 = 補回預設版型裡被刪除的種類（預設內容），每個分頁回到顯示第一個板塊；平板與電腦的方框不動（補回的板塊在那邊找空位或隱藏）。
- 手機分頁固定：行情、天氣、公車、火車、新聞、待辦，每種一個分頁（2026-10-22 起公車、火車不再合在「交通」）。停車場搜尋不在分頁列，跟其他尺寸一樣從右上角的 P 進入（2026-10-22）。
- 同類有多個板塊時一次顯示一個，**用標題兩側的左右箭頭切換**（顯示「1/3」），不用分頁標籤（2026-10-21 起：標籤會互相擠壓）。名稱太長時截成「…」，不擠壓右側的狀態列。選了哪一個存在 localStorage（`phoneCards`）。
- 某個分頁沒有該種類的板塊時，直接顯示「＋ 新增…」捷徑（不開設定視窗，內容同樣是精簡內容）。

## 5. 設定頁「顯示內容」

- 依種類分組，每組列出該類所有板塊，**每組底部有自己的「＋ 新增○○板塊」**；沒有板塊的種類顯示「看板上沒有這種板塊」。
- 任何板塊都能刪除（包括某類最後一個）；刪除要按兩次確認。刪除只在外層清單每列右側；板塊自己的設定頁不再有刪除（2026-10-22 移除，避免兩處重複）。

## 6. 板塊內容的排版

- 板塊依「所在格子的大小」排版（container query），不是依螢幕，所以換到哪個格子都正確。
- 只有一兩個項目時不要撐滿整個板塊：行情方塊最高 240px、天氣地點最高 230px；寬列的行情至少以 3 格的寬度排（2026-10-21）。
- 天氣逐時列同步捲動，所以**關掉 iOS 的回彈**（`overscroll-behavior-x: none`），否則只有被手指拖的那一列會彈。
- 標題列右側的資料問題（更新失敗、資料延遲、無即時資料）不寫成紅字，改成紅色 ⚠ 圖示：滑鼠移上去看說明（title），點了用 popover 泡泡顯示（點別處關閉）。正常的「資料 時:分:秒」仍是灰字。卡片外框變紅照舊。
- 每張卡底部一定要有資料來源列（授權要求），最小尺寸也要放得下。

## 7. 資料與 API（摘要）

- TDX 每分鐘只能查 5 次：所有公車與火車查詢經過同一個 Durable Object（`TdxGate`）共用快取與額度；使用者可自備最多 3 把金鑰輪流用。
- 輪詢對齊同一拍，同一端點的請求會合併（`getBatched`）。
- Google 新聞擋 Cloudflare 機房，所以新聞用中央社等 RSS。
- 停車場導航直接用座標開 Google 地圖（2026-10-22）。之前用「名稱＋地址」讓 Google 顯示地點資訊，但常導到同名的別處，所以放棄。
- 天氣：有氣象署測站實測就用實測（避開山區測站），沒有才用 Open-Meteo 模型，並標示來源。

## 8. 測試

- 版面系統有端對端測試：`npm run test:e2e`（Playwright + Chromium，`e2e/layout.spec.ts`）。測試會擋掉所有資料 API，只驗證版面。
- 改到版面、板塊的新增／刪除／隱藏、恢復預設、手機分頁時，先跑這組測試；新的邊緣情況請補一個測試。

## 9. 工作方式

- 使用者用繁體中文溝通；介面文字是繁體中文，程式碼註解是英文。
- 使用者常一次給多個需求，希望先分類、找出彼此的關聯再逐一處理。
